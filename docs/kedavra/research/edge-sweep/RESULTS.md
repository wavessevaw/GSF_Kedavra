# Более мягкая поправка для движения у края экрана

**Вывод: не принимать ни один из трёх вариантов.** Уменьшение коэффициента не устранило ухудшение на лестнице. Основа: v1.4.1 `5f22938b55f9853f764e927c847d9c1a8d9a8c04`; семейство гипотез описано в ветке `experiment/kedavra-edge-confidence`.

Проверялись максимальные штрафы 0,002, 0,005 и 0,01 для вектора, когда один из двух соответствующих образцов находится за кадром. Эти числа — исследовательские, а не настройки пользователя. Исходный шейдер скомпилирован из v1.4.1, варианты отличаются коэффициентом штрафа. Одинаковый тестовый исполняемый файл запускал их на Windows PC с AMD Radeon(TM) Graphics, драйвер AMD proprietary 26.10.1, Vulkan, 1280×800.

Сцены: pan, stairs, near_object, occlusion. Сравнивались генерированные SDR-кадры с математическим эталоном сцены. В таблице — число кадров, где сумма квадратов ошибки RGB по кадру уменьшилась или выросла; учитываются только изменившиеся кадры. Некоторые пиксели в одном кадре становятся лучше, а другие хуже.

| Коэффициент | Улучшились | Ухудшились | Пример ухудшения лестницы |
| --- | ---: | ---: | --- |
| 0,002 | 4 | 7 | Фаза 1/3: 49 пикселей ближе, 65 дальше от эталона |
| 0,005 | 5 | 7 | Фаза 1/3: 119 ближе, 167 дальше |
| 0,01 | 7 | 6 | Фаза 1/3: 234 ближе, 387 дальше |

Метрика и сцены не исчерпывают визуальное качество и не являются игровым испытанием. Тем не менее все коэффициенты дают наблюдаемую регрессию на приоритетной для пользователя геометрии, поэтому снижение штрафа само по себе не является обоснованным решением. `sweep-results.json` содержит все 13 кадров на вариант, включая неизменившиеся; `run_sweep.py` воспроизводит тест при наличии тестовой сборки. [Сборка шейдеров](https://github.com/wavessevaw/GSF_Kedavra/actions/runs/40499923426).

Производительность GPU для этих трёх коэффициентов, задержка ввода, TDP и Steam Deck RADV не измерялись. Эксперименты не устанавливались пользователю и не меняли рабочую ветку main.
