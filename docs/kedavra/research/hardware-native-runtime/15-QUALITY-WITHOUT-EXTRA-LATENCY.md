# 15. Качество без дополнительного ожидания: второй аудит shaders

Дата: 25 октября 2026. GitHub Releases повторно проверен: последний официальный stable — v1.4.1, SHA `5f22938b55f9853f764e927c847d9c1a8d9a8c04`. Исследовательские patches не применены к runtime. Условия: не добавлять буферизацию, задержку ввода или энергопотребление ради улучшения изображения. Процент выигрыша не заявляется.

## Результат и приоритет

1. **Q1: сохранять смысл visibility в repair общего поля пары.** Найден новый конкретный конфликт исполняемых путей: repair применяет временное смещение веса к B уже при t=0.5, хотя warp рассчитывает это смещение для каждого выходного t. Исправление убирает лишнюю операцию и не добавляет чтений текстур. Улучшение изображения — HYPOTHESIS до GPU corpus.
2. **P1: три чтения вместо пяти в sharp при точном выравнивании по оси.** Алгебраическое сокращение подтверждено моделью. Производительность на RDNA 2 не измерена; новый branch может съесть экономию. Не округлять почти целые координаты ради попадания в fast path.
3. **Продолжить прежние ME SAD cache и исправление edge duplicate skip** из [12](12-RELEASE-1.4.1-OPTIMIZATION-AUDIT.md). Это ранее найденные, а не новые достижения. Первые два кандидата и прежние исправления проверять независимо, затем совместно.

## Q1: repair повторно смещает visibility к B

Исполняемая цепочка:

- [kfg_plan.h:388](https://github.com/wavessevaw/GSF_Kedavra/blob/5f22938b55f9853f764e927c847d9c1a8d9a8c04/kedavra/engine/kfg_plan.h#L388) строит общий selection при t=0.5 и `KFG_FLAG_PAIR`.
- [kfg_plan.h:287–299](https://github.com/wavessevaw/GSF_Kedavra/blob/5f22938b55f9853f764e927c847d9c1a8d9a8c04/kedavra/engine/kfg_plan.h#L287) передаёт тот же t и флаг обеим repair-стадиям.
- [kfg_select.comp:98](https://github.com/wavessevaw/GSF_Kedavra/blob/5f22938b55f9853f764e927c847d9c1a8d9a8c04/kedavra/shaders/kfg_select.comp#L98): при изменении выбранного вектора `best.z = mix(best.z, t<0.5?0:1, smoothstep(...))` без проверки PAIR. При t=0.5 всегда выбирается направление к B.
- [kfg_warp.comp:126](https://github.com/wavessevaw/GSF_Kedavra/blob/5f22938b55f9853f764e927c847d9c1a8d9a8c04/kedavra/shaders/kfg_warp.comp#L126) трактует z как visibility ratio, пересчитывает его для текущей фазы и снова применяет confidence lean к ближайшему исходнику.

**CONFIRMED для кода:** поле после repair может содержать уже смещённый вес, хотя consumer считает его исходным отношением видимости. Срабатывает только если repair действительно выбрал другой вектор и ошибка достаточно велика. Доля таких блоков неизвестна. Две repair-стадии способны переносить уже смещённый вес дальше; это не означает обязательное двойное изменение каждого блока.

Численный пример при выбранном соседнем векторе: z=0.5, error=0.15. Repair превращает z в 0.75. На фазе 1/3 warp получает итоговый вес B=0.30 вместо 0.166667 при нескорректированном ratio. Это доказательство отличия весов, **не доказательство лучшего ground truth**. Более свежий B может случайно улучшать некоторые сцены.

Предложение: в `repair()` выполнять этот mix только без `KFG_FLAG_PAIR`. Сохранять существующий per-phase путь, порядок кандидатов, условия early return, cost, tie-break и vector winner. Patch: [pair-repair-visibility.patch](evidence/quality-cost/pair-repair-visibility.patch).

Новые структуры данных, GPU images, host interfaces и синхронизация не нужны. Владение буферами, количество source frames, scheduler и deadlines прежние. Для A/B нужен отдельный shader variant/hash; переключение/откат — через выбор baseline runtime в плагине после завершения игры. Менять установленные shader-файлы во время исполнения нельзя. Governor получает прежние метрики, частоты и TDP не меняются.

Риски: z соседа всё ещё унаследован из другого блока, а `.w` имеет неоднородный смысл; эта правка их не решает. Удаление bias может усилить двоение там, где старый bias случайно помогал. Отменить при ухудшении HUD, границ occlusion, временной стабильности или качества худших кадров, даже если средняя метрика выросла.

## P1: axis-aligned sharp

[tap_sharp():13–38](https://github.com/wavessevaw/GSF_Kedavra/blob/5f22938b55f9853f764e927c847d9c1a8d9a8c04/kedavra/shaders/kfg_warp.comp#L13) выполняет пять bilinear samples. Если дробная часть x равна ровно нулю, горизонтальные крайние коэффициенты нулевые: остаются три вертикальные выборки. Аналогично для y. Полностью целочисленные позиции уже обходят sharp через texelFetch — повторно считать их новой экономией нельзя.

Patch [axis-sharp-three-taps.patch](evidence/quality-cost/axis-sharp-three-taps.patch) добавляет fast path только при точном равенстве. Сохраняет нормировку и обработку отрицательного scRGB. Модель на конечных числах дала идентичный результат, но float32/FMA, NaN/Inf и sampler edge behaviour на GPU ещё не проверены. Это два исключённых texture instructions на активную сторону **только в fast path**, не сокращение всего warp на 40% и не измеренная экономия DRAM.

Новых буферов, очередей и кадров ожидания нет. Риски: divergence, дополнительный код/VGPR, редкое попадание в fast path после subpixel refinement и интерполяции поля. Проверить горизонтальные/вертикальные pans и смешанные движения отдельно. Отказаться при регрессии диагональных сцен, spills, росте p95 GPU time или отсутствии эффекта на репрезентативной смеси. Fallback — прежний shader, отдельный ключ pipeline cache для каждого варианта.

## Что не предлагается включать вслепую

- **Больше temporal history/ожидание следующего кадра:** против условия пользователя; не включать ради PSNR.
- **Отключить blur везде:** экономит taps, но способно усилить ступенчатость. Нужен отдельный визуальный A/B; это не доказанная оптимизация качества.
- **Увеличить radius или число repair rounds:** добавит вычисления. Сначала исправить контракт и убрать дубли.
- **Пересчитать residual после subpixel для всех blocks:** потенциально точнее, но новый cost вызывает 20 bilinear luma samples на блок. Пока не соответствует цели сокращения работы.
- **Поднять priority всего Gamescope:** может задержать игру. Более ранний synthetic frame не доказывает улучшение input latency.
- **Заменить пороги confidence:** до выравнивания смысла `.w` между select и repair это плохо контролируемая настройка. В select хранится penalized pre-refinement cost, у заменённого repair блока — новый raw cost. Исследовать отдельно, не смешивать с Q1.

## Проверки и их границы

`tools/prove_quality_cost.py` проверяет SHA blob исходников, создаёт patches и выполняет 20 000 случаев контракта repair плюс 20 000 случаев алгебры sharp. [proof.json](evidence/quality-cost/proof.json) содержит результат и ограничения. Модель repair начинает с уже выбранного нового вектора; она не доказывает частоту срабатываний полного поиска. Численные проверки sharp используют Python double, не native Vulkan.

Воспроизведение с чистым checkout v1.4.1:

```sh
python3 docs/kedavra/research/hardware-native-runtime/tools/prove_quality_cost.py --source-root /path/to/v1.4.1 --output-dir /tmp/kedavra-quality-cost
```

Попытка GLSL/SPIR-V compile новых вариантов на подключённом Deck закончилась SSH timeout. Новая компиляция **не подтверждена**, GPU execution не выполнялся. Старые compile results из главы 13 не распространяются на эти patches.

## Следующий эксперимент, достаточный для решения

1. Применить каждый patch отдельно в изолированном checkout; compile glslang и spirv-val. Не менять main и пользовательский runtime. Для Q1 проверить также `kfg_per_phase_select=1`: результат должен остаться прежним.
2. В GPU fixture для Q1 создать mixed-motion neighbourhood, где own error >=0.02, spread>1 и сосед выигрывает repair при raw residual 0.10–0.20. Readback поля до/после каждого repair, затем warp на t=1/3, 1/2, 2/3. Добавить mirror A/B и границы экрана. Отсутствие замены вектора делает fixture непоказательным.
3. Корпус: статичный HUD, текст/субтитры, тонкие ограды, лестницы/повторяющиеся текстуры, pan по обеим осям, диагональ, движущийся объект с открытием фона, scene cut, SDR/HDR. Измерять ошибки отдельно по маскам HUD/occlusion/edges и временную стабильность; сохранять худшие кадры. Среднего PSNR недостаточно.
4. P1 сравнить baseline/proposal readback при целой одной координате, дробных обеих, clamp на границе, отрицательном scRGB. Зафиксировать расхождения float32; не выдавать CPU algebra за bitwise GPU identity.
5. На RADV сравнить A/B/A: одинаковый input, shader hashes, разрешение, фильтры и power policy; минимум несколько прогретых блоков, затем игровые 10-минутные блоки в 30→90, 45→90, 30→60 и 24→90. Записывать анализ, warp, game frame time, repeat/skip, phase progression, мощность и температуру. Для очень малого эффекта нужны повторения и оценка разброса.
6. Проверить scheduler trace: не добавлен новый источник ожидания, source age не вырос. Для утверждения о фактическом input-to-photon нужен оптический метод; unchanged buffering — архитектурное свойство, а не измеренная задержка ввода.
7. При положительном результате — отдельная экспериментальная сборка с установкой, откатом, переключателями и диагностикой в плагине. Журнал: версия/hash, variant, capabilities, причины fallback, pipeline creation errors; никакого синхронного disk logging в paint path. По умолчанию baseline до завершения A/B.

Аппаратные наблюдения после пользовательских изменений RAM/TDP/GPU — не контрольная группа. Стабильность кастомных таймингов не доказана; ошибки такого стенда нельзя автоматически приписывать shader patch. Исследовательские сборки сначала проверять при известной стабильной конфигурации, не меняя её без пользователя.
