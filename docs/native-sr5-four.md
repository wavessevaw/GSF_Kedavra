# SR.5: four real frames, regularized inverse

Four source frames from the six-slot engine ring, including the displayed real frame or generated pair anchor. The selected chain has three submitted bidirectional flow fields. Current display geometry is a registration reference and Focus spatial prior, never an additional synthetic observation. For each 5x5 tile the four 4x4 native sample lattices have their own fractional positions. The 9x9 spatial prior includes a fixed 2-pixel halo. Forward model: exact pixel area, mild [0.05,0.90,0.05] separable blur; local normal equation 64 observations / 25 unknowns, lambda 0.012, 8 PCG iterations, 0.9 bounded luma correction. Gating: scene cut, inconsistent flow, out of frame, alpha, insufficient sampling diversity, local photometric confidence. Fallback is SR.3 spatial, not single-frame inverse. FG-off captures and analyzes real frames with the existing engine ring (cost not measured).

CPU model on five photographs and two degradation models, known shifts of (0,0),(1,0),(0,1),(1,1) HR pixels: SR.3 PSNR 32.46857 dB, SSIM 0.93652, HF correlation 0.71567. Four-frame local area-only inverse 38.63824 dB, SSIM 0.95619, HF corr 0.85185. Selected mild-blur inverse 37.20608 dB, SSIM 0.95964, HF corr 0.85548, HF RMS relative error 0.50393 vs 0.71621 prior. Motion errors degrade recovery; model and performance are unverified on Deck. These CPU results assume known shifts and do not test confidence coverage or game content. Runtime uses local motion refinement and rejects unreliable tiles, so results will differ. A five-pixel local tile seam and frame-time budget are key hardware validation risks.

Vulkan test verifies four measured lattices improve on synthetic reference, cuts fall back, and the normal registration path does not substantially regress it. Exact-registration test sets a harness-only flag. Production uses motion estimation and two native-luma LK refinement steps. Focus is forced by GFG, no extra UI controls.
