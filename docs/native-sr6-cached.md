# SR.6: source-rate inverse cache and FG-first budget

SR.5 performed the full four-frame solve for every displayed phase. Deck testing reported ~27 FPS and PACE 60–70 with FG enabled. SR.6 isolates the inverse from Focus and normal post-processing, reconstructs signed luma residuals on real anchors only, and reprojects them with the existing selected pair motion at generated phases. Cache identity is tied to actual source commit IDs and invalidated on ring overwrite/reset/post changes. The six-slot ring lazily allocates one RGBA8 residual per reconstructed frame. At most one heavy reconstruction per source interval. A timestamp guard suspends SR temporal work for 4–32 seconds after a composite exceeds its existing GPU budget. Spatial SR.3 and Focus remain active. No new UI controls.

CPU comparison, identical five photographs, synthetic shifted observations, two degradations, known motion and approximate Focus: SR.3 PSNR 32.46857, SSIM 0.93652, HF corr 0.71567; 8-iteration SR.5 37.20608, 0.95964, 0.85548; four iterations with bilinear halo 35.46544, 0.95510, 0.82205. These do not measure cached generated phases or Deck performance. Exact Vulkan tests exercise cache quantization/merge against direct solver and existing cut/registration checks. The budget guard may disable the temporal improvement if it cannot coexist with FG. Hardware FPS, PACE, temporal consistency and GPU timings are required.
