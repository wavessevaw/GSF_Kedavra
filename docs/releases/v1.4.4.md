**GSF 1.4.4 Kedavra**: the game keeps its own frames. A game just under the base cap no longer drops towards half of its frame rate when generation is on, and the picture responds sooner.

Install: Decky → Settings → Developer → Install plugin from zip → `GSF-Kedavra-1.4.4.zip`, then **Setup → Reinstall Gamescope KEDAVRA** and reboot (the engine changed). The zip installs over 1.4.3 in place. Details: [README](https://github.com/wavessevaw/GSF/blob/v1.4.4/README.md).

### New in 1.4.4

- **No more falling to half the frame rate.** The base cap releases one game frame per slot (45 fps at 90 Hz: a slot of two refreshes). A frame that finished just after the start of its slot used to wait for the whole next slot, so a game rendering at 44 fps under a cap of 45 was shown at about 30 and a 37 fps game at about 22. Such a frame now goes through on the very next refresh, and the game keeps the rate it can render.
- **Lower latency.** A game frame no longer waits for its slot, so it reaches the screen sooner, also in games that hold the cap.
- **Same cadence when the cap holds.** A game that is on time still gets exactly one frame per slot, on the cap's own 2-2-2-3 pattern for fractional caps.

Scheduler simulator (`kfg_sim`, 90 Hz, 3 seeds × 120 s, the game waits for each frame to be shown before it starts the next one), 1.4.3 → 1.4.4:

| Case | Game frames per second | Median latency |
|---|---|---|
| ×2 (cap 45), game renders 46.5 fps | 33.7 → 38.3 | 49.5 → 38.5 ms |
| ×2 (cap 45), game renders 43 fps | 27.3 → 34.1 | 66.1 → 43.8 ms |
| ×2 (cap 45), game renders 37 fps | 22.9 → 30.1 | 64.1 → 52.0 ms |
| ×2.25 (cap 40), game renders 38 fps | 20.6 → 30.2 | 81.9 → 49.1 ms |
| ×2 (cap 45), game holds the cap | 42.9 → 44.3 | 48.8 → 38.7 ms |

Missed refreshes stay under 0.13 % in every case (target < 0.5 %).

**GSF 1.4.4 Kedavra**: игра сохраняет свои кадры. Игра чуть ниже лимита базы больше не проваливается к половине своей частоты кадров при включённой генерации, а картинка откликается быстрее.

Установка: Decky → Настройки → Разработчик → Установить плагин из zip → `GSF-Kedavra-1.4.4.zip`, затем **Setup → Reinstall Gamescope KEDAVRA** и перезагрузка (движок изменился). Zip ставится поверх 1.4.3. Подробно: [README](https://github.com/wavessevaw/GSF/blob/v1.4.4/README.ru.md).

### Новое в 1.4.4

- **Больше никакого провала к половине частоты.** Лимит базы пропускает один кадр игры на слот (45 FPS при 90 Гц: слот в два обновления экрана). Кадр, готовый чуть позже начала слота, раньше ждал весь следующий слот, поэтому игра, рисующая 44 FPS под лимитом 45, показывалась примерно на 30, а игра на 37 FPS примерно на 22. Теперь такой кадр проходит на ближайшем обновлении, и игра сохраняет ту частоту, которую может рисовать.
- **Меньше задержка.** Кадр игры больше не ждёт свой слот, поэтому раньше попадает на экран, в том числе в играх, которые держат лимит.
- **Тот же ритм, когда лимит держится.** Игра, которая успевает, по-прежнему получает ровно один кадр на слот, а при дробном лимите в его ритме 2-2-2-3.

Симулятор планировщика (`kfg_sim`, 90 Гц, 3 прогона × 120 с, игра ждёт показа каждого кадра, прежде чем начать следующий), 1.4.3 → 1.4.4:

| Случай | Кадров игры в секунду | Медианная задержка |
|---|---|---|
| ×2 (лимит 45), игра рисует 46,5 FPS | 33,7 → 38,3 | 49,5 → 38,5 мс |
| ×2 (лимит 45), игра рисует 43 FPS | 27,3 → 34,1 | 66,1 → 43,8 мс |
| ×2 (лимит 45), игра рисует 37 FPS | 22,9 → 30,1 | 64,1 → 52,0 мс |
| ×2,25 (лимит 40), игра рисует 38 FPS | 20,6 → 30,2 | 81,9 → 49,1 мс |
| ×2 (лимит 45), игра держит лимит | 42,9 → 44,3 | 48,8 → 38,7 мс |

Пропущенных обновлений экрана меньше 0,13 % во всех случаях (цель < 0,5 %).
