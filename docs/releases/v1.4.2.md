**GSF 1.4.2 Kedavra**: lower latency, steady speed at every multiplier including fractional ones like ×2.25, and no jump after a game stall.

Install: Decky → Settings → Developer → Install plugin from zip → `GSF-Kedavra-1.4.2.zip`, then **Setup → Reinstall Gamescope KEDAVRA** and reboot (the engine changed). The zip installs over 1.4.1 in place. Details: [README](https://github.com/wavessevaw/GSF/blob/v1.4.2/README.md).

### New in 1.4.2

- **Lower latency.** Motion analysis takes about 2.5 ms, so it now runs in one pass right after the composite and the pair is usable on the next refresh instead of two refreshes later. A slower analysis (heavy scenes, 4K) is still split in two so it never delays a composite. The GPU work is the same.
- **Steady speed at every multiplier.** 1.4.1 kept the delay at the lowest value it had ever reached, so every slightly late game frame caused a slow-down followed by a speed-up. A slow-down is no longer paid back with a speed-up: the picture keeps its delay and gives a refresh back only after a calm second. Near the lowest delay that held, a give-back that runs short is tried again later each time, so a game with jittery frame times settles at the delay it needs.
- **Fractional bases on their real rhythm.** At 90 Hz, base 40 (×2.25) releases the game on a 2-2-2-3 refresh pattern and base 35 (×2.6) on its own pattern. The scheduler expects each frame where the pattern puts it, not at the mean, and a frame latched a refresh late is put back on the pattern.
- **No jump after a stall.** After a game stall at ×2 the long interval was filled with a single intermediate and the picture then jumped ahead. Intervals up to 2×multiplier+4 refreshes are now filled one refresh at a time.
- **Centred HUD panel.** The HUD bitmap can now be placed in the centre of the screen (corner 4), for short messages such as a plugin's benchmark notice.

Scheduler simulation, 1.4.1 → 1.4.2, 3 seeds × 180 s per case. "Speed changes" is the share of refreshes where the picture moves at a visibly different speed. Latency is the display delay behind the newest frame.

Stable base (the game holds its cap with room):

| Case | Speed changes | Latency |
|---|---|---|
| ×2, 90 Hz, base 45 | 0 → 0 % | 33.3 → 22.2 ms |
| ×2.25, 90 Hz, base 40 | 77.8 → 0 % | 37.8 → 33.3 ms |
| ×2.6, 90 Hz, base 35 | 0 → 0 % | 44.4 → 33.3 ms |
| ×3, 90 Hz, base 30 | 0 → 0 % | 44.4 → 33.3 ms |
| ×3.75, 90 Hz, base 24 | 6.7 → 0 % | 55.3 → 44.4 ms |
| ×2, 60 Hz, base 30 | 0 → 0 % | 50.0 → 33.3 ms |
| ×2.4, 60 Hz, base 25 | 83.3 → 0 % | 60.4 → 50.0 ms |

Game close to its cap, with occasional 50 ms spikes:

| Case | Speed changes | Latency | Jumps per minute |
|---|---|---|---|
| ×2, 90 Hz, base 45 | 43.6 → 1.6 % | 40.9 → 36.0 ms | 8.9 → 0 |
| ×2.25, 90 Hz, base 40 | 2.9 → 1.5 % | 44.6 → 36.7 ms | 0 → 0 |
| ×3, 90 Hz, base 30 | 25.1 → 1.1 % | 49.9 → 46.1 ms | 0.4 → 0 |

With a game that misses its cap, the lower delay leaves less room to hide a late frame, so a late frame shows as a short hold more often (×2.25 near the cap: 2.7 → 8.0 per minute); Autopilot lowers the base for such a game.

**GSF 1.4.2 Kedavra**: меньше задержка, ровная скорость на всех множителях, включая дробные вроде ×2.25, и нет скачка после подвисания игры.

Установка: Decky → Настройки → Разработчик → Установить плагин из zip → `GSF-Kedavra-1.4.2.zip`, затем **Setup → Reinstall Gamescope KEDAVRA** и перезагрузка (движок изменился). Zip ставится поверх 1.4.1. Подробно: [README](https://github.com/wavessevaw/GSF/blob/v1.4.2/README.ru.md).

### Новое в 1.4.2

- **Меньше задержка.** Анализ движения занимает около 2,5 мс, поэтому теперь он идёт одним проходом сразу после композита, и пара готова к следующему обновлению экрана, а не через два. Более долгий анализ (тяжёлые сцены, 4K) по-прежнему делится на две части, чтобы никогда не задерживать композит. Работа GPU та же.
- **Ровная скорость на всех множителях.** 1.4.1 держал задержку на самом низком значении, какого когда-либо достиг, поэтому каждый чуть опоздавший кадр игры давал замедление, а за ним ускорение. Теперь замедление не отыгрывается ускорением: картинка сохраняет задержку и отдаёт обновление только после спокойной секунды. Если у самой низкой удержанной задержки отдача не удалась, следующая попытка ждёт дольше, и игра с неровным временем кадра оседает на той задержке, которая ей нужна.
- **Дробная база в её настоящем ритме.** При 90 Гц база 40 (×2.25) выпускает игру по ритму 2-2-2-3 обновления, база 35 (×2.6) по своему. Планировщик ждёт каждый кадр там, где его ставит ритм, а не по среднему, а кадр, пойманный на обновление позже, возвращается на ритм.
- **Нет скачка после подвисания.** После подвисания игры на ×2 длинный промежуток заполнялся одним промежуточным кадром, и картинка прыгала вперёд. Теперь промежутки до 2×множитель+4 обновлений заполняются по кадру на обновление.
- **HUD по центру.** Картинку HUD теперь можно вывести в центр экрана (угол 4), для коротких сообщений вроде уведомления о замере в плагине.

Симуляция планировщика, 1.4.1 → 1.4.2, 3 сида по 180 с на случай. «Смены скорости» — доля обновлений, на которых картинка идёт с заметно другой скоростью. Задержка — отставание картинки от новейшего кадра.
